# LightGBM 小资金实盘执行清单

生成日期：`2026-05-22`

## 0. 当前定位

本清单用于把 LightGBM 财务过滤选股研究结果转换成**小资金、人工确认、低频执行**的实盘流程。

当前不建议直接全自动下单。第一阶段定位应为：

> 模型给候选，人工做最后确认；每周低频执行；严格控制仓位和回撤。

当前首选候选规则：

```text
bp_value_q70_max8_cash25_buffer24
```

中文解释：

```text
强低 PB 代理过滤：BPS/close 高于当日截面 70% 分位；
最多持有 8 只股票；
至少保留 25% 现金；
每周调仓；
旧持仓只要排名仍在前 24 名就优先保留。
```

选择它的原因：

- 相比成长线，最大回撤更小。
- 在 40 万资金、单只 3 万以上约束下，基本能持满 8 只。
- 平均现金比例稳定在约 `25%-27%`，更适合第一阶段防守。

## 1. 实盘前硬约束

### 1.1 资金约束

| 项目 | 第一阶段规则 |
| --- | --- |
| 总资金 | 约 `40` 万以内 |
| 股票目标仓位 | 不超过 `75%`，约 `30` 万 |
| 现金保留 | 不低于 `25%`，约 `10` 万 |
| 最大持仓数 | `8` 只 |
| 单只目标金额 | 约 `3.5-4.0` 万 |
| 单只最低买入金额 | 低于 `3` 万不买 |
| 单周最大新增 | 不超过 `2-3` 只 |

### 1.2 策略边界

以下情况不执行买入：

- MiniQMT 行情数据没有更新到最近一个交易日。
- 财务缓存不存在，或本周未确认可读取。
- 候选列表少于 `12` 只。
- 目标股票出现 ST、停牌、明显异常公告、连续涨停后无法合理买入。
- 当周账户已触发暂停条件。
- 用户本人无法盯盘或无法接受当周潜在亏损。

## 2. 每周执行节奏

建议频率：

```text
每周一次，优先周末或周一盘前生成候选；
周一或本周第一个交易日人工确认；
确认后分批下单，不追涨。
```

如果周一是节假日，则顺延到本周第一个交易日。

## 3. 周度准备清单

每周生成候选前，先逐项确认：

| 检查项 | 是否通过 |
| --- | --- |
| MiniQMT 已启动并可连接 | `[ ]` |
| 本地日线行情已更新到最近交易日 | `[ ]` |

| 当前账户总资产、可用资金、持仓已记录 | `[ ]` |
| 本周没有触发暂停交易条件 | `[ ]` |

## 4. 候选生成流程

### 4.1 准备财务缓存

如果本周没有更新财务缓存，先运行：

```powershell
d:\python_envs\gd_qmt_env\python.exe code\ml_stock_selection\prepare_financial_data.py --stock-batch-size 100 --tables PershareIndex
```

注意：

- 财务数据不应在模型主流程中自动下载。
- 如果下载失败，不要强行实盘买入。
- 失败明细看：

```text
code/ml_stock_selection/outputs/financial_cache/financial_download_failures.csv
```

### 4.2 生成最新财务增强预测

全市场财务增强版运行示例：

```powershell
d:\python_envs\gd_qmt_env\python.exe code\ml_stock_selection\lightgbm_multi_factor_stock_selection.py --use-financial-factors --start-date 20200101 --end-date <最新交易日> --min-prediction-date <最近需要预测的日期>
```

说明：

- `<最新交易日>` 用最近本地日线完整日期，例如 `20260521`。
- `<最近需要预测的日期>` 可以设为最近几个月的日期，避免重跑过多无关输出。
- 输出目录形如：

```text
code/ml_stock_selection/outputs/lightgbm_multi_factor_stock_selection/<run_id>
```

## 5. 候选人工复核

模型给出的候选不直接买入。每只股票至少看下面几项：

| 检查项 | 通过标准 |
| --- | --- |
| 是否 ST / 退市风险 | 不能买 |
| 是否停牌或即将停牌 | 不能买 |
| 最近是否连续涨停 | 不追涨，跳过 |
| 当天是否一字板或接近涨停 | 不追涨，跳过 |
| 最近是否重大利空公告 | 谨慎，默认跳过 |
| 20 日成交额是否足够 | 已在模型中过滤，但仍人工确认 |
| 单只买入金额是否能达到 3 万 | 不足则跳过 |
| 买入后是否超过单只仓位上限 | 超过则缩小或跳过 |

如果人工复核后可买股票少于 `5` 只，本周不新增仓位，只保留旧持仓或观望。

## 6. 下单规则

### 6.1 买入规则

第一阶段买入规则：

- 单只目标金额：`3.5-4.0` 万。
- 单只最低买入金额：`3` 万。
- 按 `100` 股整数倍下单。
- 不用市价单追涨。
- 如果开盘大幅高开，不立即买，等待回落或放弃。
- 本周最多新增 `2-3` 只。

### 6.2 保留规则

旧持仓满足以下条件时优先保留：

- 仍在模型排名前 `24` 名。
- 没有触发单只止损。
- 没有重大利空或流动性异常。

### 6.3 卖出规则

卖出触发条件：

- 旧持仓跌出排名前 `24`。
- 单只亏损达到 `-8%~-10%`。
- 股票出现 ST、重大利空、流动性异常。
- 账户级风控要求降仓。
- 人工确认基本面或交易状态异常。

卖出优先级：

1. 先卖出触发硬风控的股票。
2. 再卖出跌出排名缓冲的股票。
3. 最后才考虑正常换仓。

## 7. 账户级风控

按 `40` 万资金估算：

| 触发条件 | 约亏损金额 | 动作 |
| --- | ---: | --- |
| 账户回撤 `-5%` | `2` 万 | 暂停新增买入，只允许卖出和减仓 |
| 账户回撤 `-8%` | `3.2` 万 | 股票仓位降到一半 |
| 账户回撤 `-10%` | `4` 万 | 停止策略，重新复盘 |
| 单日亏损超过 `-2%` | `0.8` 万 | 当天不再开新仓 |
| 连续 2 周亏损 | 视情况 | 下一周只允许保留，不新增 |
| 连续 3 周亏损 | 视情况 | 暂停一周，重新复盘 |

如果这些亏损金额不能接受，应降低实盘资金，而不是继续调参数。

## 8. 单只股票风控

| 风控项 | 动作 |
| --- | --- |
| 单只浮亏 `-5%` | 加入观察，不补仓 |
| 单只浮亏 `-8%` | 减半或退出 |
| 单只浮亏 `-10%` | 原则上退出 |
| 单只盈利超过 `20%` 后快速回撤 | 至少减半锁定收益 |
| 出现 ST / 重大利空 | 不等模型，优先退出 |

第一阶段不做补仓摊低成本。

## 9. 盘中行为限制

禁止事项：

- 不因为盘中上涨临时追买模型外股票。
- 不因为单日大涨临时加仓。
- 不在亏损后手动补仓摊平。
- 不把保留现金全部打满。
- 不同时启用多个未验证策略。

允许事项：

- 因涨停无法买入时跳过。
- 因高开过多时跳过。
- 因账户触发风控时提前减仓。
- 因明显数据异常时暂停执行。

## 11. 每周复盘

每周至少复盘一次：

| 项目 | 要回答的问题 |
| --- | --- |
| 本周是否按清单执行 | 有没有临时主观加仓 |
| 模型候选是否可买 | 是否经常涨停、高开或流动性不足 |
| 实际持仓数 | 是否能稳定持有 6-8 只 |
| 现金比例 | 是否低于 25% |
| 换仓数量 | 是否超过 2-3 只 |
| 最大单只亏损 | 是否触发止损 |
| 本周相对指数表现 | 是策略问题还是市场整体问题 |

## 12. 暂停实盘条件

任一条件触发，暂停新增买入：

- 账户回撤达到 `-5%`。
- 模型候选连续两周明显不可买。
- 财务缓存或行情数据出现异常。
- 实际执行偏离清单，例如连续追涨或补仓。
- 用户无法连续跟踪持仓风险。

任一条件触发，停止策略并复盘：

- 账户回撤达到 `-10%`。
- 单月亏损超过 `-8%`。
- 同一周出现多只股票同时触发硬止损。
- 回测逻辑与实盘成交行为明显不一致。

## 13. 第一阶段实盘建议

第一阶段不追求收益最大化，只验证三件事：

1. 模型候选是否真的能买到。
2. `8` 只股票 + `25%` 现金是否能承受波动。
3. 自己是否能严格按规则执行。

建议第一阶段至少观察 `4-8` 周。若执行稳定，再考虑：

- 把现金保留从 `25%` 降到 `10%`。
- 或少量加入成长进攻线。
- 或开发正式的候选导出和人工确认脚本。

当前不建议：

- 直接上成长线。
- 直接满仓。
- 直接自动下单。
- 同时交易超过一个模型版本。
